# TasteTrend Gen AI POC - RAG pipeline validation

# Query Validation Framework

The purpose of this document is to demonstrate alignment with three success criteria specified in the SOW: 

* **Query Accuracy** - Natural language queries return relevant results with >80% accuracy based on manual validation

* **Response Time** - API queries return results within 3 seconds for 95% of requests

* **Query Variety** - System successfully handles at least 5 different query types (ratings, sentiment, comparisons, trends, specific feedback)

This validation is designed for local execution directly testing live RAG pipeline to eliminate the operational and cost overhead of cloud-hosted test infrastructure. 

Related files:

* **[Test Queries](../tests/test_queries.json)** - Includes representative samples across all five query categories: ratings, sentiment, comparisons, trends, and specific feedback. One sample per category plus an extra query for testing guardrail rules.

* **[Validation Script](../tests/validate_RAG_pipeline.py)** - Validation script simulating end-to-end customer API calls to trigger the RAG pipeline and evaluate downstream response generation. Outputs a MD file containing the response.

* **[RAG Evaluation Results](../tests/rag_evaluation_results_20260826_014239.md)** - Contains the response generated by the validation script.

The validation script sends real HTTP POST requests to the deployed API Gateway endpoint (not a local or mocked call), simulating how an external client would invoke the RAG system. For each of the 6 test queries [Test Queries](../tests/test_queries.json), it records the HTTP status, response latency, and full generated answer to [RAG Evaluation Results](../tests/rag_evaluation_results_20260826_014239.md).

Each result includes an automated keyword-match check against expected_keywords. The "PASSED/FAILED" label in the output isn't real accuracy validation: a test only "passes" if at least one expected_keyword string literally appears in the answer text. A correct, well-grounded answer can still show as "FAILED" here if it paraphrases rather than using the exact expected wording.

Additionally, the validator checks for active policy interceptions. Upon detecting an authorized guardrail refusal, it automatically marks the test status as PASSED and appends GUARDRAIL_INTERCEPTED to the matched keywords log.
